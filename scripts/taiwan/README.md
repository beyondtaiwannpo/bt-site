# 台灣海岸線是怎麼來的

首頁那座島不是手畫的，是從真實地理資料算出來的。
這個資料夾放的是「怎麼再算一次」，不然下一個人只會看到 HTML 裡一串四千字的座標，
不知道從哪來、也不敢改。

## 一句話

拿 g0v 的 2010 縣市邊界，把**只被用過一次的邊界線**挑出來（縣市之間共用的內部界線會被用兩次，
只有海岸線是用一次），接成封閉的環，投影成平面座標，再簡化到 370 個點。

## 檔案

| 檔案 | 是什麼 |
|---|---|
| `twCounty2010.topo.json` | 原始資料。g0v `twgeojson`，TopoJSON 格式，25 個縣市，1913 個座標點 |
| `build-coastline.py` | 產生腳本。跑 `python3 build-coastline.py` |
| `coastline.txt` | 產出。主島一條 path，離島七條，加 viewBox 與投影參數 |
| `cities.json` | 16 個城市投影後的 SVG 座標。島上的光點用這個定位 |

## 怎麼重跑

```
cd scripts/taiwan
python3 build-coastline.py
```

沒有第三方套件，只用 Python 標準函式庫。跑完會印出一張 ASCII 版的台灣，
**一定要看一眼**，確認形狀還是台灣再把 `coastline.txt` 的內容貼回頁面。
這一步不是多餘的：投影或篩選改壞的時候，數字看起來都很正常，只有圖會告訴你。

## 幾個刻意的決定

- **不含金門與馬祖。** 它們在西邊 118.3 度與北邊 26.1 度，放進來整個版面會被撐爆，
  島本身就變小了。腳本用經緯度範圍篩掉（`lon<119.2 or lat>25.45`）。
  哪天要加回來，改那一行，但版面要重排。
- **澎湖、蘭嶼、綠島留著。** 它們讓這座島看起來是真的，不是一個圖案。
- **投影用等距圓柱加 cos 修正**，不是 Web Mercator。範圍只有三個緯度，
  兩者差異看不出來，但這樣少一個函式庫也少一個會壞的地方。
- **簡化到 370 點**（RDP，eps 0.55）。再細看不出差別，檔案卻會變兩倍。
  島要放更大的話再把 eps 調小重跑。
- 外框長寬比 0.528。看起來比「台灣寬 144 公里」寬是正常的，
  因為東西兩個極點分別在北部和中部，島是斜的。
