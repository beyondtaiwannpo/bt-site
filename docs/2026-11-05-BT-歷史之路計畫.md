# BT 歷史之路 `/history/`：計畫與自我檢查迴圈

Paul 2026-11-05 看了 asklex.law/journey 之後定的：做一頁「BT 怎麼走過來」，捲動就沿著一條路往前走，每一站可以點開看那一年的說明與照片，後台可以自己加站。

參考站是 Three.js 的 3D 村莊。我們做 2.5D 插畫路（Paul 同日拍板），理由：零建置、手機跑得動、明年的幹部改得動。

## 要做成什麼

**前台 `/history/`**
- 一條斜向的路，分層的 inline SVG（天空、遠山、路、低多邊形的房子、樹、人），用 Brand Book 七色，跟首頁的島與 `/alumni/` 航線圖同一套語言。
- GSAP ScrollTrigger 把場景釘住，捲動就沿路前進，各層視差做出深度。`prefers-reduced-motion` 的人看到的是一條直立的靜態時間軸。
- 每一站一個小場景加一張卡片（年份、標題）。底部一條年份帶、進度「03 / 07」、鍵盤左右鍵跳站。
- 點一站：覆蓋層滑進來，日期、中英說明、照片牆（手機滑、桌機燈箱）。「回到路上」關掉，捲動位置不變。每站有自己的網址 `#2023-bootcamp`，IG 可以直連。
- 右上：Play journey（自動捲）、中英切換。不掛 `nav.js` 頂欄，只放一個回首頁的 logo。
- 資料與動畫分離：場景是固定程式，站從資料庫來。加一站永遠不碰場景程式。

**後台 `/admin/site/` 新分頁「History」**
- 站的清單、新增、編輯、拖拉排序、上傳照片、兩把鑰匙上架（編輯的人標 ready，Co-President 或 Senior Adviser 按上架），跟 Events 同一套。
- 照片一定要勾「拍攝同意已確認」才能上架，程式擋，不靠人記得。照片不標名字。
- 誰能編：Marketing 工作區「管」的人加 senior，跟 Events 一樣。
- 照片放 Supabase Storage 的 `history` bucket，瀏覽器端先縮到 1600 寬再上傳。
- 第一批資料：`/impact/`「五年走過來」那七點先塞進去，上線第一天不是空的。

## 資料表（批 1 定案，之後只加不改）

- `milestones`：id、slug、happened_on（date）、title_zh/en、summary_zh/en、body_zh/en、sort（int）、status（draft/ready/published/archived）、published_by/at、created_by/at、updated_at。
- `milestone_photos`：id、milestone_id、url、caption_zh/en、consent（boolean，預設 false）、sort。
- 沒登入只讀得到 published 的站與它們 consent=true 的照片，用 security definer 的 `public_milestones()` 回 JSON，不開表。

## 守住的事

- 不加框架、不加 build step、GSAP 只從 cdnjs 載並帶 SRI、`motion()` 包著。
- 不碰 `index.html` 文案。`/impact/` 那七點維持，只是多了一條路可以點。
- 有未成年人的照片：同意沒勾不上架，照片不標名字，這兩條寫進資料庫函式不是寫在 UI。

  |---|---|---|---|---|---|---|
  | 首頁 | 100 | 100 | 1201ms | 1501ms | 0.000 | 466KB |

### 批 3（2026-11-06 開工：場景重畫、收尾、效能）

Paul 看完批 2 的結論：能用、是 BT 的樣子，但畫面太平，離 asklex.law/journey 很遠。這一批把場景重畫到 2.5D 的 SVG 做得到的極限，再把收尾與效能做完。

**參考站靠什麼做出深度（開工前先看一遍寫下來的）**：它是 Three.js 的 3D 村莊，鏡頭架得高、斜四十五度往下看，路是一條從左下往右上退進霧裡的斜帶，近處寬、遠處窄，所以「遠」這件事是透視畫出來的，不是用顏色暗示的。每棟房子看得到三個面（受光的牆、背光的牆、屋頂），光從同一個方向來，地上有一道朝右下的長影，影子把物件釘在地上。沿路有人、牛車、汽車自己在動，跟捲動無關，所以畫面在你停下來的時候也活著。遠處用霧把顏色往天空推（空氣透視），地平線那一條看不到邊。底部年份帶是「大年份、小標籤、橘線」的節奏，右下一張卡貼著建築，左上一個淡淡的大年份。捲動不是換頁，是鏡頭沿路往前走，每一站鏡頭會停一下。**我們的對應**：鏡頭用真的針孔投影（每一幀重算每個物件的位置與大小），路因此自己收窄進霧裡；物件是平面貼圖（billboard），本身畫了受光面、背光面、屋頂與長影；遠近用大小、重疊、霧、影四件事說；路上有公車、機車、走路的人自己動；底部年份帶與左上大年份照它的節奏。做不到的是繞著建築看（貼圖只有一個角度）與真的光影，那是 Three.js 的事。

開工前寫的驗收清單。做完一項打一個勾，沒做到的留空並寫為什麼。

場景（`history/src/scene.js`、`history/history.css`）
- [x] 鏡頭是高角度四分之三視角：路是一條從左下往右上、近寬遠窄退進霧裡的斜帶；站的位置是沿路算出來的點（`world()` 給 Z，`project()` 給螢幕座標），卡與小場景站在算出來的點上。
- [x] 捲動是鏡頭沿路前進（每一幀重新投影），靠近每一站鏡頭稍微放大、卡浮上來。
- [x] 至少五層深度各自不同速度：遠山與霧、遠景樹列與田、路邊建築、路與路邊的東西、近景框住角落的植物；遠的東西淡進天空色（空氣透視）。
- [x] 每個物件底下有朝同一個方向的長影，光的方向一致。
- [x] 天空從 2020 的早晨慢慢變成最後一站的黃昏（漸層隨進度換），幾朵慢慢飄的雲。
- [x] 路上有自己會動的東西（公車、機車、走路的人、天上的鳥），用 `<symbol>` 加 `<use>` 重複用，檔案不膨脹。

- 霧：從中景就開始把顏色往天空推，遠處的房子只剩淡淡的輪廓，地平線那一條看不到邊。霧的顏色跟天空一樣（奶油白），不是灰。夜景那一段霧變成深藍。
