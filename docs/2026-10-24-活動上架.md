## 少什麼

一場「活動」今天在系統裡只是一份表單加一堆申請，**沒有一個對外的樣子**。少的是：

1. **每一場活動一頁對外頁**：封面圖、中英標題、日期、地點、名額、說明、「報名」按鈕。
2. **首頁一段「近期活動」**：三張卡，開頁時從資料庫讀；資料庫休眠就整段不出現，不留一個壞掉的框。
3. **`/events/` 活動總覽頁**：近期的、過去的。
4. **活動的狀態**：草稿 → 公開 → 過去了。表單的 draft／open／closed 是報名開不開，不是活動公不公開，兩件事要分開。
5. **封面圖**：GOALS 說對外頁面不加新照片除非確認同意範圍，而且檔案不進 repo。所以封面是 team 自己貼一條 Drive 或 Cloudinary 的圖片網址，**公開前要勾「這張照片裡的人與那場活動都在拍攝同意範圍內」**。

## 「各 team 自己設計自己的活動」是什麼、不是什麼

**是**：在後台填標題（中英）、封面網址、日期、地點、名額、說明（中英），再用現有的題目編輯器排報名表的題目。
**不是**：拉版面、換配色、放影片的頁面編輯器。活動頁的長相整站一套（跟首頁同一個設計系統），team 填的是內容。做頁面編輯器會把這個 repo 變成沒有人接得住的東西（GOALS「明確不做」那一節的理由）。

## 設計

### 資料

一張表 `events`：

| 欄 | 是什麼 |
|---|---|
| `id` uuid、`slug` text unique | 網址用的代號（英文、數字、連字號），從英文標題自動算 |
| `team` text | 哪個 team 的 |
| `workspace_id` text | `custom:event-<slug>`，這場活動的工作區（成員、看／改／管） |
| `form_id` uuid → forms | 報名表（一場一份；沒有表單就是「只公告不報名」） |
| `title_zh`、`title_en`、`summary_zh`、`summary_en`、`body_zh`、`body_en` | 標題、一句話、說明 |
| `cover_url` text、`cover_consent` bool | 封面圖網址、同意勾了沒 |
| `starts_at`、`ends_at` timestamptz、`place` text、`capacity` int | 時間、地點、名額（0 是不限） |
| `status` | `draft`／`ready`／`published`／`archived`（過去了是算出來的：`ends_at < now()`，不另外存） |
| `published_by`、`published_at` | 誰在什麼時候放上對外頁 |
| `created_by`、`created_at`、`updated_at` | |

RLS：
- 沒登入的人（anon）只讀 `status = 'published'`，而且只讀對外要印的欄位（用一支 `public_events()` 函式回，不開表給 anon）。
- 這場活動工作區「看」以上讀全部欄位；「改」以上改內容；「管」或 team 的 Director 可以按「準備好了」（ready）。
- `published` 只有 Co-President 與 Senior Adviser 按得了（第一題）。
- 報名表那一側一個字不動：報名就是 `applications`，RLS、審核、簽到、信照舊。

### 對外三個地方

- **`/events/`**：一個資料夾一個 HTML（repo 規矩）。開頁用 `public_events()` 讀，列近期的（`ends_at >= now()`，照開始時間），底下「過去的活動」（第三題）。不載 supabase-js，用瀏覽器的 `fetch` 打那一支函式（網址與公開金鑰寫在頁面裡，`check.sh` 守著跟 `shared/supabase.js` 一樣）。讀不到就只印「活動載不到，等一下再來」一行。
- **一場活動的頁**：`/events/?e=<slug>`，同一個 HTML 讀網址上的代號再畫（GitHub Pages 是靜態的，不能一場活動一個資料夾）。封面、標題、日期、地點、名額與已報名人數、說明、「報名」按鈕連到 `/apply/?f=<form_id>`。報名表還沒開放就印「X 月 X 日開放報名」。
- **首頁「近期活動」**：一段三張卡（封面、標題、日期、地點），開頁時 `fetch` 一次，**讀不到或沒有活動就整段 `hidden`**，跟團隊頁「一個人都還沒公開就整段不出現」同一個做法。卡片連到那一場的頁。文案只有段落標題一句（第二題）。

### 後台

- 側欄「申請」那一組多一行「活動」：清單（這一屆的活動、狀態、報名數）、「開一場活動」（先選 team，建工作區與表單一起建好）、一場活動的編輯頁（內容欄位、封面與同意勾選、報名表連到現有的表單編輯頁、成員分頁、簽到、行前信的入口都在同一頁）。
- 「準備好了」按下去，Co-President 的總覽多一張卡「等上線的活動：N」，點進去看一眼封面與文案，按「放上對外頁」。
- People → Workspaces 的那個 team 那一列多一格（跟自訂工作區一樣，自動）。

### 前後對照

**Director 開一場活動**
- 現在：People → Workspaces 開一個自訂工作區（1）、`/admin/#forms` 開一份表單選 team（2）、排題目（3）、開放（4）、自己想辦法把活動放到 IG 或 LINE，官網上沒有它。首頁永遠是六段定稿文案。
- 之後：後台「活動 → 開一場活動」填內容與封面（1）、排報名表題目（2）、勾同意、按「準備好了」（3）、Co-President 按「放上對外頁」（4）。活動頁、`/events/`、首頁「近期活動」同時出現。報名開放日到了表單自己開。

**路人從首頁報名**
- 現在：首頁看不到任何活動；要知道有活動得先聽說，再找到 `/apply/`。
- 之後：首頁第三段看到三張卡（1）、點進活動頁看時間地點說明（2）、按「報名」到 `/apply/`（3）、登入或註冊四欄位（4）、填題目送出（5）。收到信的流程照舊。

## 要 Paul 決定的五題（括號是建議）

1. **誰可以把活動放上對外頁。** （建議：兩道鑰匙，跟團隊頁一樣。活動工作區「管」的人按「準備好了」，Co-President 或 Senior Adviser 按「放上對外頁」。首頁是 BT 的門面，一張沒對過的封面或文案放上去，撤下來副本也不會消失。）
   另一條路：工作區「管」的人自己放上去，Co-President 事後撤。
2. **首頁「近期活動」放哪一段。** 首頁文案是定稿，加一段就是改首頁。（建議：放在「我們做什麼」那一段之後、「加入我們」之前，中英各一段；段落標題「近期活動」「Upcoming」，只有這一句新文案要 Paul 點頭。沒有活動的時候整段不出現，首頁跟現在一模一樣。）
3. **過去的活動要不要留在 `/events/` 上。** （建議：留，列在「過去的活動」底下，最近 12 個月。這是 BT 做過什麼的證據，嘖嘖頁會用到。活動頁留著但「報名」變成「已結束」。）
4. **報名要不要登入。** 今天 `/apply/` 要登入（註冊四欄位加電子報同意，那個帳號就是嘖嘖要的名單）。（建議：維持要登入。不登入的報名拿不到同意勾選，名單累積了也不能寄；而且簽到、錄取信都綁帳號。代價是多一步，活動頁上要寫清楚「報名要先登入，一分鐘」。）
5. **名額到了怎麼辦。** （建議：硬關，報名數到名額表單自動關、活動頁印「額滿」。候補名單是另一套狀態與另一封信，第一版不做；要的話之後加一個 `waitlisted` 狀態。）

## 不做

- 不做頁面編輯器（上面講過）。
- 不上傳檔案：封面是連結。照片同意是 team 自己勾、Co-President 放上去前再看一眼，兩道。
- 不做活動的留言、按讚、分享數。
- 不動 `/apply/` 的註冊與同意流程。
- 不動 `shared/`：首頁與 `/events/` 用的那一小段 `fetch` 各自寫在自己的頁面裡。

## 安全這一輪

- anon 只拿得到 `public_events()` 回的欄位，表本身不開給 anon。
- 報名走現有的 `applications` RLS，沒有新的門。
- 封面網址只收 `https://`，活動頁用 `<img>` 不用 CSS 背景，壞掉的連結就是一張破圖不是整頁壞。
- 首頁的 `fetch` 失敗、超時（3 秒）都走同一條路：整段 `hidden`。
