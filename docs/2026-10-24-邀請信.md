# 邀請信：打一個 email 跟他之後的職位，寄一封信把人請進來

2026-10-24。給 Paul 看的。這一輪只有設計，沒有動程式、沒有遷移檔，你拍板了再做。

你的原話：「我要能邀請人進後台，主要是校友，打他的 email 跟他收到信之後會是什麼職位，信的版面要好看，或者讓我自己設計那個版面。」

今天的做法是你發一組碼、用別的管道貼給他、他自己登入後打碼。這一份把它變成：**打 email 與職位，按一下，信就寄出去，他點信裡的連結登入就是那個職位。**

幾個詞先講一次：

- **邀請碼**：`invite_codes` 表的一列。今天已經有，而且 10-24 起可以綁著名單上的一筆紀錄（他拿碼進來就認領那一筆，歷屆職位在他身上）。
- **outbox**：`mail_outbox` 表，要寄的信先排在這裡，`send_pending_mail()` 一封一封交給 Resend 寄。錄取信、面試信今天都走這條。
- **信的文案**：`mail_templates` 表，一種信一列，你在後台「信件文案」改主旨與內文、右邊即時預覽。
- **認領**：`claim_invite()`，登入之後拿碼換身分的那支函式。

## 0. 要 Paul 拍板的事

每題一行回我就好，其他照建議做。

1. **碼多久過期？** 建議 **30 天**。過期的碼在清單上標「已過期」，一顆「重寄」會換一組新碼、重算 30 天。
2. **信要不要綁 email？** 綁的意思是：他一定要用收信的那個 email 登入（密碼或 Google 都可以，只看登入的 email），不然認領不了。**可以做到**：`claim_invite()` 把碼上記的 email 跟登入 token 裡的 email 比，對不上就擋。代價是他若用另一個 Google 帳號登入會被擋，畫面會說「這組碼是寄給 xxx@ 的，請用那個帳號登入」，你再重寄到另一個 email 就好。**建議綁。** 不綁的話，信被轉寄就等於碼被轉手。
3. **要不要「已開信」這個狀態？** 做法是信裡的連結打開 `/app/?invite=碼` 時，頁面叫一支沒登入也能叫的小函式，把那組碼的「開過」時間記下來（只寫時間，不回任何東西）。清單上就看得出「寄了但沒點」跟「點了但沒登入」。**建議做**，一支十行的函式，讓你不用猜信有沒有進垃圾桶。
4. **誰能邀請、誰能撤？** 邀請：Co-President 與 Senior Adviser（跟改名單一樣）。重寄：同一群。撤銷：只有 Co-President。**建議照這樣。**
5. **邀請時填的職級與職位怎麼生效？** 碼上記著職級；他認領的那一刻 `claim_invite()` 把職級寫進去並記一筆變動紀錄；職位與 team 在邀請當下就建好名單紀錄與這一屆的職位（跟「加一筆過去的紀錄」同一條路），認領時那一筆歸到他。**建議照這樣。** 校友沒有職級，只有職位（例如「Director, Curriculum Team · 2024-25」）。
6. **寄件人。** 信從現有的那個位址寄（Vault 的 `BT_MAIL_FROM`，錄取信同一個）。GOALS.md 的規矩是電子報不能走這個網域，但這不是電子報：一次一封、對方認識你、信裡是給他個人的連結。**建議照舊。** 信尾還是那一句「不要回覆這封信，有問題寄到 beyondtaiwan2020@gmail.com」，`{sender}` 是你（邀請的人）的名字，印在信裡。
7. **舊的批次碼（一組碼很多人用）留不留？** 2026-09 發給三十位幹部那一次用的就是它。**建議留著**，收在「邀請」頁最底下一個摺疊「批次碼（給一整批人同一組碼）」，平常不用看到。

## 1. 使用者看到什麼

### 1-1. 你（Co-President）：後台 → People → 邀請

「邀請碼」改叫「**邀請**」。頁首底下一張表單，六格：

| 格 | 必填 | 說明 |
|---|---|---|
| Email | 是 | 信寄到這裡，碼也綁這個 email（第 0 段第 2 題） |
| 他會是 | 是 | 下拉：Co-President、Senior Adviser、Director、Adviser、Associate（幹部五級）、校友、實習生 |
| 職位 | 校友必填，幹部選填 | 跟改一個人那一頁同一個下拉（五級加自訂），加 team、屆別。幹部沒填就用職級推（Director 加 Curriculum Team 就是「Director, Curriculum Team」） |
| 名字 | 選填 | 中英文各一格。有填就先建名單紀錄；沒填就等他註冊時自己填 |
| 給他的一句話 | 選填 | 會印在信裡「{sender} 說：」那一行 |
| 備註 | 選填 | 只有後台看得到 |

按「寄邀請信」：建名單紀錄（有名字或職位才建）、建一組綁 email 的碼、排一封信進 outbox、立刻叫 `send_pending_mail()` 寄出去。左下角 toast：「邀請信寄給 xxx@ 了，碼是 bt-xxxxxx」。

底下是清單，一人一列：email、他會是什麼、狀態與日期、備註。狀態五種，徽章裡一定有字：

| 狀態 | 什麼時候 | 列尾有什麼 |
|---|---|---|
| 寄出 | 信在 outbox 寄成功了 | 重寄、撤銷 |
| 寄失敗 | outbox 試了五次都沒成（Resend 的錯誤印出來） | 重寄、撤銷 |
| 開過信 | 他點了連結但還沒登入認領（第 0 段第 3 題） | 重寄、撤銷 |
| 認領了 | `invite_uses` 有他那一筆，印他的名字 | 連到名單上那一筆 |
| 過期／撤銷 | 30 天到了、或你撤了 | 重寄（換新碼） |

「重寄」換一組新碼、重算 30 天、再排一封信；舊碼作廢。「撤銷」是 inline confirm，碼立刻失效，名單上的紀錄留著（跟刪人同一個規矩：紀錄不丟）。

### 1-2. 他（收到信的人）

信是純文字（跟錄取信一樣，Resend 那一路現在只送 `text`；要 HTML 版面是另一個決定，見第 4 段）：

```
主旨：Beyond Taiwan 邀請你加入後台　You are invited to Beyond Taiwan

{name} 你好，

{sender} 邀請你加入 Beyond Taiwan 的後台，你的身分會是 {position}。
點這個連結，用這個 email 登入（或用 Google 登入同一個 email），就完成了：

{link}

進去之後第一眼是「總覽」：你被派進哪些工作區、今天要處理的事。
護照、時間看板、設定在最上面那一條。
這個連結 30 天內有效，只有你能用。

{sender} 說：
（他填的那一句話）

Hi {name},

{sender} has invited you to the Beyond Taiwan admin as {position}.
Open this link and sign in with this email (or Google on the same email):

{link}

The first thing you will see is the Overview: your workspaces and what needs handling today.
The link is valid for 30 days and works only for you.

不要回覆這封信，這個信箱沒有人看。有問題請寄到 beyondtaiwan2020@gmail.com。

Beyond Taiwan
```

中英各一段是 BT 慣例（校友在七個國家）。這整段是**預設文案**，存在 `mail_templates` 的 `invite` 那一列，你在後台「信件文案」改，右邊即時預覽，五個代換符號：`{name}`、`{position}`、`{term}`、`{link}`、`{sender}`。沒填名字的人 `{name}` 會是「你好」前面空著，所以預設文案第一行是「{name} 你好」，空的時候會變成「 你好」；預覽會讓你看到。

連結是 `https://beyondtaiwannpo.com/app/?invite=bt-xxxxxx`，**網址上只有碼，沒有 email、沒有名字**。

### 1-3. 他點進來之後（`/app/`）

1. `/app/` 看到 `?invite=`：把碼收進 sessionStorage（跟 `?next=` 同一招，網址上的東西不當網址用），畫面上方一條「你收到的是邀請連結，用收信的那個 email 登入或註冊就好」。順手叫一次「開過了」（第 0 段第 3 題）。
2. 他登入或註冊（密碼或 Google）。
3. 登入成功，`/app/` 發現口袋裡有碼，自動叫 `claim_invite(碼)`。成功：幹部進總覽、校友進設定頁（跟今天一樣）。失敗：留在 `/app/` 印原因，三種人話：「這組碼是寄給 xxx@ 的，你現在登入的是 yyy@」「這組碼過期了，請邀請你的人重寄」「這組碼已經用過了」。
4. 不用再有「我有邀請碼」那一格；它留著給舊的批次碼。

## 2. 資料庫怎麼改（一支遷移檔 `2026-10-29-invites.sql`，接在 `2026-10-28-adviser-rank.sql` 後面）

### 2-1. 表

`invite_codes` 加六欄，都可以空（舊的批次碼不填）：

| 欄 | 做什麼 |
|---|---|
| `email` | 綁定的 email（小寫存） |
| `rank` | 認領時要寫進 `board_role` 的職級（只有 `grants = 'cadre'` 才有） |

### 2-2. 函式（門都在第一句）

| 函式 | 門 | 做什麼 |
|---|---|---|
| `invite_person(email, grants, rank, name_zh, name_en, title_en, title_zh, team, term, line, note)` | `require_senior()` | 一次做完：email 正規化並檢查格式；同一個 email 還有一組沒用的碼就擋（`invite_pending`）；有名字或職位就建 `people` 一列與那一屆的職位；碼是 `bt-` 加 8 個隨機英數（不是你打的，少一個要想的欄位）；`uses_left = 1`、`expires_at = now() + 30 天`、`email`、`rank`、`invited_by`；用 `mail_templates.invite` 填好主旨與內文排進 outbox；回那組碼 |

| `revoke_invite(code)` | `require_president()` | `uses_left = 0`、`revoked_at = now()`。紀錄留著 |
| `invites_for_review()` | `require_senior()` | 清單：每一組碼的 email、grants、rank、名單紀錄、狀態（照上面那張表算）、最後一封信的 `sent_at` / `error`、認領的人 |

### 2-3. 驗收表（遷移檔最後印）

## 4. 信的版面：純文字，或 HTML

你說「版面要好看，或者讓我自己設計」。今天 Resend 那一路只送 `text`（`send_pending_mail()` 組的 JSON 只有 `text` 一欄），所以錄取信、面試信都是純文字，而純文字在 Gmail 裡就是等寬字加一條連結。

兩條路：

- **(a) 維持純文字**，文案寫好、段落短、連結獨立一行。你在後台改得動，預覽就是寄出去的樣子。零風險。
- **(b) 加 HTML 版面**：`send_pending_mail()` 多送一個 `html` 欄，用一個固定的殼（米白底、深藍字、logo、一顆「登入」按鈕）把 `text` 的段落包起來。你改的還是文字，殼不給改（一個會被三十個人的手機與 Gmail 打開的 HTML，不是後台該讓人編的東西）。多一支小遷移檔改 `send_pending_mail()`，而且**四封既有的信也會一起穿上這個殼**，因為它們走同一支。

**建議 (a) 先上、(b) 另開一題。** 理由：邀請信的價值在「點了就進得去」，不在版面；而 (b) 會動到錄取信那條已經在跑的路，要單獨測、單獨問你。你要 (b) 的話我把殼畫成一張 HTML 給你看過再做。

## 5. 自檢

### 安全

| 項目 | 怎麼守 |
|---|---|
| 碼單次 | `uses_left = 1`，跟綁紀錄的校友碼一樣 |
| 碼會過期 | `expires_at`，`claim_invite()` 擋，清單標「已過期」 |
| 碼綁 email | `claim_invite()` 比 `auth.jwt() ->> 'email'`；Google 登入的 email 也在 token 裡，所以兩條登入路都擋得住。**可以做到，改的只有 `claim_invite()` 一支** |
| 網址沒有個資 | 只有碼。email、名字、職位都在資料庫 |
| 信被轉寄 | 第 2 題綁 email 之後，轉寄的人登入的 email 對不上，擋 |
| 誰能邀 | `require_senior()`；撤 `require_president()`；清單 `require_senior()`（有 email） |
| `invite_opened` 沒有門 | 只寫 `opened_at`、只在第一次、回 void。拿它探碼存不存在探不到（回的東西一樣） |
| 邀請當下建的名單紀錄 | 跟「加一筆過去的紀錄」同一支路，沒人認領就一直是「沒有帳號」，永遠不上對外頁（10-24 的規矩） |
| 一個 email 兩組活的碼 | 擋（`invite_pending`），要先撤或重寄 |
| 寄信 | 走既有 outbox，一次一封，不是群發；寄件網域照舊（第 6 題） |
| 認領寫職級 | 只在 `claim_invite()` 裡、只在 `grants = 'cadre'`、記變動紀錄。前端沒有任何路徑設職級 |
