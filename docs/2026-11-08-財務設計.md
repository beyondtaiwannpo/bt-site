# 財務（2026-11-08）：資料模型與誰看得到

Paul 2026-11-07：「總共多少錢、花在哪、收入，全部」。他同一天拍板的預設：
看的人是 Co-President、Senior Adviser、Sponsorship 的 Director；改的人是 Co-President 與 Sponsorship 的 Director；
從今天每個帳戶的餘額開始記，不補舊帳；嘖嘖撥款整筆當一筆收入。
這一頁寫的是資料長什麼樣、為什麼這樣定。怎麼用在 README「財務」。

## 五張表

| 表 | 一列是什麼 | 重點欄位 |
|---|---|---|
| `fin_accounts` | 錢放在哪裡 | 中英名、種類（bank／cash／platform）、幣別、**開帳餘額**、**開帳日**、順序、封存時間 |
| `fin_categories` | 收支分哪幾種 | 種類（income／expense）、中英名、`code`（seed 用，後台加的沒有）、順序、封存時間 |
| `fin_transactions` | 每一筆進出 | 日期、種類（income／expense／transfer）、金額、幣別、**台幣**、匯率、帳戶、轉入帳戶、類別、對象、備註、收據路徑、屆、誰登的、作廢時間／誰／原因 |
| `fin_budgets` | 某屆某類支出的預算 | 屆、類別、台幣；唯一鍵 (屆, 類別) |
| `fin_log` | 每一次新增、改、作廢 | 表名、列 id、動作、誰、時間、前、後（jsonb）。trigger 寫，沒有人改得動 |

## 幾個刻意的決定

- **從今天的餘額開始，不補舊帳。** 餘額 = 開帳餘額 + 開帳日起的收入 − 支出 − 轉出 + 轉入。開帳日之前的筆就算登了也不算進餘額（那些錢已經在開帳餘額裡），但照樣算進那一屆的收支。Paul 的理由：舊帳在別的地方，補回來要一個人花好幾天，而且對不上就會一直對不上。
- **轉帳不是收入也不是支出。** 從銀行領現金是搬家，不是花掉。總覽的收支不動，兩個帳戶的餘額一減一加。
- **台幣由資料庫算。** 金額 × 匯率四捨五入到分，前端填的台幣不信。美金那一筆存原幣、匯率、台幣三個，之後對帳看得出當時的匯率。
- **登錯的不刪，作廢。** 作廢留時間、誰、原因；作廢過的不能再改也不能再作廢。帳本不該有消失的列。
- **每一次寫都留前後值。** `fin_log` 由 trigger 寫，不靠函式記得呼叫。要看誰改了什麼查這張表。
- **嘖嘖撥款整筆一筆。** 類別「募資」，手續費另登一筆支出「手續費」。不拆成每一位贊助者（那是嘖嘖後台的事）。
- **屆由日期算。** 一筆登在哪一屆看 `terms` 的日期範圍，都不在就是 current。預算也是照屆。
- **收據放私人 bucket。** 沒有公開網址，看走簽名網址（十分鐘）。路徑用筆的 id 加時間與亂數，不用原檔名（原檔名可能有人名或金額）。只收圖與 PDF、5 MB。
- **沒有圖表函式庫。** 每月長條圖是自己畫的 SVG（repo 不從 CDN 載東西，GSAP 是唯一例外）。
- **CSV 帶 BOM。** Excel 看到 BOM 才用 UTF-8 開，沒有的話中文是亂碼。列尾 `\r\n`，逗號引號換行照 RFC 4180 包起來。

## 誰看得到、誰改得動

```
can_view_finance() = is_senior()            或 is_sponsorship_director()
can_edit_finance() = is_president()         或 is_sponsorship_director()
is_sponsorship_director() = 幹部，而且這一屆（terms.status = current）positions 裡
                            team 是 Sponsorship（^sponsorship，不分大小寫）、title_en 含 director
```

- 五張表 RLS 只有一條：`select` 給 `can_view_finance()`。**沒有 insert／update／delete 的政策**，表的權限也只 grant select，寫一律走函式。
- 六支寫的函式第一句 `fin_require_edit()`，三支讀的函式第一句 `fin_require_view()`。
- anon 對五張表與所有 `fin_*` 函式都沒有權限。
- Storage `receipts`：讀 `can_view_finance()`、傳改刪 `can_edit_finance()`，bucket `public = false`。
- 側欄怎麼知道：`my_access()` 在能看的人的 workspaces 陣列尾巴多一個 `{ id: "finance", level: "view" | "edit" }`。前端 `shared/auth.js` 本來就把那個陣列變成 `{ id: level }` 存進分頁快取，所以側欄的 `who: "ws:finance"` 不用動任何讀取路徑，也不用多一趟請求。代價：重跑 2026-10-24 那支會把 `my_access()` 蓋回沒有 finance 的版本，要再跑一次 11-08。
- 為什麼不做一個真的工作區：工作區是「派人進去」的東西，而財務是**職位帶來的**（Sponsorship 的 Director 換人就自動換），不該有人在工作區頁面把隨便一個人派進財務。

## 前端

- `/admin/finance/` 是第五個後台資料夾，外殼跟其他四個一模一樣（五份逐字比對）。
- 數字在瀏覽器算（`ui.js` 的 `overview()`），資料庫的 `fin_overview()` 是同一條公式：smoke 驗 SQL、node 驗 JS。兩邊算的一樣才對；哪天不一樣，先懷疑開帳日那一條規則。
- 整張 `fin_transactions` 一次讀下來（一年幾百筆），篩選在瀏覽器做，匯出也從同一份篩好的列組 CSV。到了幾萬筆再分頁。
