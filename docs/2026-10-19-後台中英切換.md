# 後台的中英切換（2026-10-19）

Paul 2026-10-19：「後台加一個中英切換，像對外網站那樣，預設英文。」
這份寫做法與理由。做完的使用說明在 `README.md`「後台的中英切換」。

## 對外網站是怎麼做的

對外七頁中英兩版都寫在 HTML 裡，`<html data-lang="zh|en">` 決定顯示哪一版。
選擇的順序：網址上的 `?lang=` 先，沒有就看瀏覽器語言。
**刻意不用 localStorage**（`about/index.html` 第 55 行的註解）：對外網站不在任何人的裝置上存東西，
讀者包含未成年人。頁尾的 `keepLang()` 把 `?lang=` 補到每一條站內連結上，選擇跟著人走。

## 後台為什麼不能照抄

後台的字不在 HTML 裡，是每個資料夾的 `ui.js` 用 JS 樣板字串畫出來的，`data-lang` 藏不掉一版。
所以**選擇的機制沿用**（同一個 `?lang=` 參數、同樣是 `zh` 與 `en` 兩個值），**字的來源改成一本字典**。

後台跟對外網站有一點不一樣：後台一定是登入的幹部，瀏覽器裡本來就有 Supabase 的登入票。
所以後台多存一個 `localStorage` 的 `bt-lang`，選過一次之後下次登入還是那個語言。
對外網站的「不存東西」那條原則是為了未成年的讀者，後台的使用者是幹部，不衝突。
**順序：`?lang=` 先，再 `localStorage`，兩個都沒有就英文。** 不看瀏覽器語言，因為 Paul 說預設英文。

## 做法

### 一個資料夾一本字典：`admin/<資料夾>/src/strings.js`

四個後台資料夾（`admin/`、`admin/site/`、`admin/passports/`、`admin/people/`）各自一支，
不互相 import（跟 `esc()`、側欄那一段同一條規矩）。每一支長這樣：

```js
export const COMMON = {               // 四份一模一樣的那一段：側欄、五個小零件、共用按鈕
  "common.save":   { zh: "存起來", en: "Save" },
  ...
};
export const MINE = {                 // 這一組自己的畫面
  "forms.title":   { zh: "申請表", en: "Forms" },
  ...
};
export const STRINGS = { ...COMMON, ...MINE };
```

- 鍵是英文、用點分段（`畫面.用途`），中文與英文**並排在同一行**，下一屆的人加一個鍵不用讀程式。
- `T("forms.title")` 回現在語言的那一句。鍵不存在就回鍵本身，畫面上會看到 `forms.title` 這種字，一眼就抓得到漏翻。
- 帶數字的句子用 `{n}`：`T("forms.received", { n: 3 })`。英文單複數用 `{n:form|forms}`，
  例如 `"{n} {n:form|forms}"` 在 1 的時候是 `1 form`，其他是 `3 forms`。中文沒有單複數，照常寫。
- 側欄的 `GROUPS` 與 `ITEMS` 裡的 `label` 與 `hint` 從一句字串改成 `{ zh, en }` 兩句並排，`T()` 吃物件也吃鍵。
- 中文一句都不改，原樣搬進字典。英文：短、白話、按鈕用祈使句、句首大寫其餘小寫、不用驚嘆號、不用 emoji。
  Co-President、Director、team、intern、passport、stamp、invite code、cadre 照程式碼裡既有的用法。
- 日期維持 `YYYY-MM-DD`，不做在地化格式。

### 語言怎麼決定、怎麼切

`strings.js` 另外有四個小函式：

- `pickLang(search, stored)`：純函式，給網址的 query string 與 localStorage 裡存的值，回 `zh` 或 `en`。順序見上面。
- `setLang(l)` 與 `lang()`：現在的語言。`T()` 看它。
- `withLang(href)`：把 `?lang=` 塞進一條連結，側欄到別組的連結、首頁卡片的直達連結都過它，語言跟著走。
- `isErr(msg)`：訊息是不是「沒做成」那一種（下面說）。

`main.js` 開頁第一件事 `setLang(pickLang(location.search, localStorage.getItem("bt-lang")))`，
並把 `<html lang>` 與 `<title>` 一起換掉。側欄最上面「你是誰」那一塊底下兩顆小按鈕「中文 / English」，
現在的那一顆亮著（深藍底）。按下去：`setLang`、存 `localStorage`、`history.replaceState` 把 `?lang=` 寫進網址、`render()`。
不重新載入頁面，填到一半的東西不會不見（狀態都在 `S` 裡，畫面只從 `S` 畫）。手機上這兩顆在「後台選單」展開的那一塊裡。

### 訊息是綠的還是橘的

原本 `msgKind()` 靠中文的字尾判斷（「不起來：」「載不到：」這一類是沒做成）。英文沒有那幾個字。
改成**看字典**：鍵以 `err.` 開頭的句子都是「沒做成」，訊息裡含有任何一句（中文或英文）就是橘的。
好處是加一句新的錯誤訊息只要鍵取 `err.` 開頭，不用再去改那一條正規表示式。
`main.js` 裡 `"存不起來：" + D.says(err)` 這種組合改成 `T("err.save") + D.says(err)`。

### `says()` 的錯誤碼

每個資料夾 `data.js` 的 `SAYS` 表從 `[錯誤碼, 中文]` 變成 `[錯誤碼, 中文, 英文]`，`says()` 看 `lang()` 挑一句。
資料庫的錯誤碼（`not_president`、`invite_exists:...`）本身不動，查詢的程式一行都沒改。
`data.js` 自己 `throw new Error("表單要有名字。")` 的那幾句也改走字典。

### 四份要一樣的東西，測試守著

`test/admin-hub.test.mjs` 原本就逐字比對四份 `GROUPS`、`ITEMS` 與五個小零件。
這次加三條：四份 `COMMON` 一字不差、每個鍵 `zh` 與 `en` 都有、
每一組的每一個畫面用 `en` 畫出來之後不剩任何中文字（`[一-鿿]`），餵進去的假資料裡的中文除外。
既有測試全部斷言中文，那些檔案開頭加一行 `setLang("zh")`，一行都不用改。

## 不做的

- 不動 `shared/nav.js` 的頂欄與其他登入後的頁面（護照、時間看板、設定）。那些還是中文，這一批只做後台四組。
- 不動資料庫、不動查詢。
- 不把字典做成共用檔：四份各自一本，跟側欄那一段同一個理由（資料夾之間不互相 import），測試守著共用的那一段。
- 翻譯的是介面，不是資料。表單名、題目、城市名、intern 的中文標題都是幹部自己填的，是什麼就顯示什麼。

2. `./check.sh` 全綠。
