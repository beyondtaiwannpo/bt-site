# 官網效能實測（2026-09-07，改版批 4）

這份是**實測數字**，不是設定清單。每一行都是真的跑出來的。
量的是**線上的 beyondtaiwannpo.com**，不是本機 —— 本機沒有網路延遲，量不出海外連線的情況。

## 怎麼量的（下一個人要重跑就照這個）

```
npx --yes lighthouse@12 https://beyondtaiwannpo.com/ --output=json --output-path=home.json \
  --chrome-flags="--headless=new --no-sandbox --disable-gpu"
```

- 工具：Lighthouse 12.8.2。用 `npx` 跑，**沒有裝進這個 repo** ——
  「不加 npm 相依」那條規則沒有被打破，它是一支量測工具，不是網站的一部分。
- 不加參數就是**手機模式**：Lighthouse 預設會模擬慢速行動網路與慢的 CPU。
  那正好對應「海外幹部網路不好」這個一直以來的顧慮。
- 桌機模式加 `--preset=desktop`。
- 每一組都是冷啟動（Lighthouse 自己清快取）。

## 改了四件事，各自省下什麼

### 1. Google Fonts 的 CSS 不再擋渲染（最大的一項）

那份 CSS 有三萬多位元組（alumni 因為多一個 Iansui 是六萬多），
其中絕大部分是這一頁根本用不到的 unicode-range 片段，
卻要等它整份下載完，瀏覽器才開始畫字。**手機版實測擋住約 1.2 秒。**

改成 `media="print"` 加 `onload` 切回 `all` —— 不擋渲染載 CSS 的標準寫法。
沒有 JavaScript 的瀏覽器走 `noscript` 那一行，照舊擋渲染但一定載得到。

代價是字體一定會先用系統字再換過來。那本來就會發生（`font-display:swap`
就是這個意思），只是現在文字更早出現。

### 2. 消掉 CLS 0.219

原本以為是島的容器沒有定寬高。**實測不是** —— 加了 `aspect-ratio` 之後 CLS 一點都沒變，
那一行後來拿掉了（留一條有錯誤理由的規則，比沒有那條規則更糟）。

真正的來源是**中英兩版**。首頁的中英全文都在 HTML 裡（沒有 JavaScript 時兩版都要讀得到），
所以在瀏覽器套上 `data-lang` 之前，畫面上是「中文全文接著英文全文」。
判斷原本寫在頁尾，畫面畫完才把其中一版藏起來，下面所有東西跳一次。
把語言判斷提到 `<head>`，屬性在第一次繪製前就掛好，什麼都不跳。

### 3. 十張照片全部 lazy

這條規則原本是「第一張不 lazy、其餘 lazy」，因為當時第一張照片就是首頁的主視覺。
改版批 2 之後第一屏是那座台灣島，照片整批往下移到畫面之外，那個理由就不成立了。
首頁手機版的傳輸從 572KB 降到 400KB。
`scripts/check-photos.mjs` 的規則跟著改，並在那裡寫下哪天第一屏又換回照片就要改回來。

### 4. 對比度

alumni 手機清單的城市名是 `rgba(16,42,134,.6)`，在米白上只有約 3.6:1，
過不了 WCAG AA 的 4.5:1。提到 `.82`（約 7:1）。卡片的提示文字 `.55` 同理提到 `.75`。
**「看起來還讀得到」不等於過得了**，用 rgba 調淡的文字要記得算對比。
無障礙從 96 回到 100。

## 還沒解決的一件事：開場動畫壓住首頁手機的 LCP

首頁手機停在 79，瓶頸不是下載，是**渲染延遲佔了 82%**。
LCP 的元素是第一屏那段副標，而它在開場動畫跑完之前是看不見的
（GSAP 的 `from` 把它的透明度設成 0）。

同一頁、同一組設定，只差有沒有開場動畫：

| | 效能 | FCP | LCP | LCP 元素 |
|---|---|---|---|---|
| 有開場動畫（現在的樣子） | 79 | 3488ms | 3651ms | 那段副標 |
| 開了「減少動態效果」 | **100** | **1046ms** | **1046ms** | h1 |

**開場動畫的代價是慢速手機上多等約 2.6 秒。**

這不是 bug，是取捨：那個開場是 Paul 指定的「全站唯一需要震撼的地方」。
要換回速度的話有三種做法，都還沒做：

1. 什麼都不改。設計贏，數字就是 79。
2. 把開場縮短（現在整段約 1.8 秒）。大概能拿回 1 秒，震撼感打折。
3. 副標不做淡入、只做位移。透明度 0 的東西不算「畫出來」，改成只動位置就會早很多；
   但這樣一來開場的層次會少一層。

**這一項要 Paul 決定，不要自己選。**

## 順便驗證過的（批 4 驗收清單上的其他項）

- **GSAP 的 SRI 是對的，而且真的擋得住。**
  線上實測 `window.gsap` 是 `object`，代表雜湊比對通過、瀏覽器願意執行它。
  （中間一度量到 `undefined`，那是量測時多加了一個 `Cache-Control` 請求標頭，
  讓那個跨來源請求變成需要預檢而被擋掉 —— 是量測方法的問題，不是網站的問題。）
- **Google Fonts 加不了 SRI。** 同一個網址，Google 會依瀏覽器回不同的 CSS
  （新舊兩個 User-Agent 實測差 7KB、sha384 完全不同），雜湊必然對不上。
  Paul 2026-09-07 選擇維持現況。完整說明在 `docs/2026-09-07-官網視覺方向.md`。
- **中文字體確實有 subset 與 swap。** 實測那份 CSS：首頁 129 個 `@font-face` 區塊，
  129 個都有 `font-display: swap`、129 個都有 `unicode-range`；
  alumni 是 237 個，同樣全部都有。Noto Sans TC 只要了 900 一個字重。
  瀏覽器只會下載這一頁真的用到的那幾片，常用漢字那一片約 13KB。
- **隱私政策的第三方清單**中英兩版都補上了 cdnjs（Cloudflare）。
