起因是你的原話：「我要重新 Design 一次我的 BT 後台，現在看起來超亂超不知道在幹嘛。我要弄成像是 BT dashboard 一樣，每個人每個 team 都有自己的地方在做，整齊直接，可以看出來在幹嘛，以後要加功能可以加。」

第一次重整（2026-10-15，`docs/2026-10-15-後台重整盤點與設計.md`）把後台拆成四個資料夾、功能補齊，那六個決定這次不重提，全部照舊：後台只管資料庫裡本來就有的東西、team 的守門、改職位一人就能改但留紀錄、護照活動只給 Co-President、拆資料夾、這一季做到批 3。

文件分四段：第一段是我真的登入看完的盤點（截圖在 `docs/admin-redesign/before/`），第二段是兩個方案比較加建議，第三段是三輪自檢的紀錄，第四段是拍板後怎麼分批做。

幾個詞先講一次：

- **資訊架構**：東西放在哪、怎麼分組、點幾下到得了。這次要改的主要是這個。
- **側欄**：畫面左邊一條固定的選單，列出所有地方，你在哪一格會亮。Gmail、Notion 左邊那條就是。
- **空狀態**：清單裡一筆都沒有的時候畫面長什麼樣。好的空狀態會告訴你「接下來做什麼」。
- **`board_role`**：幹部裡管到哪。畫面上一律叫「職位」：一般幹部、Director、Co-President。
- **RLS**：資料庫層的規則，決定誰看得到、動得了哪幾列。前端改不掉它。這次整份設計都不碰它。

## 2. 設計

### 2-1. 首頁長什麼樣

登入後第一眼不是目錄，是**三塊**，由上到下：

**第一塊：你是誰、管到哪。** 一行字：「王平，Co-President，Sponsorship Team」。這一行是整個後台「我有什麼權限」的唯一來源，之後看到灰掉的東西，回來看這一行就知道為什麼。

**第二塊：今天要處理的事。** 幾張小卡，每張一個數字、一句話、一顆直達的按鈕。只畫你管得到的，不畫你管不到的：

| 卡 | 誰看得到 | 數字從哪來 | 按下去到哪 |
|---|---|---|---|
| 還沒處理的申請 N 件 | 所有幹部（自己 team 的）、Co-President 全部 | `loadForms()` 已經有的 `counts.received` 加總 | `/admin/`，第一份有待審的表單 |
| 還沒寄出去的信 N 封 | Director 與 Co-President | `loadPendingAll()` 已經有 | 同一張卡上直接「現在寄出去」 |
| 等你核可上團隊頁 N 人 | Co-President | 新的 `loadTodo()` 數 `public_profile = true and public_approved = false` | `/admin/site/#team` |
| 等你核可上校友頁 N 人 | Co-President | `loadTodo()` 數 `stories_for_review()` 的筆數 | `/admin/site/#stories` |
| 這一屆 intern N 位，平均蓋了 M 格 | Internship team、Co-President | `loadTodo()` 數 `intern_passports` 與 `intern_stamps` 的筆數，只數不拿人名 | `/admin/passports/#interns` |
| 幹部 N 位，其中 M 位還沒填 team | Co-President | `loadTodo()` 讀 `profiles` 的數量 | `/admin/people/#roster` |

數字是 0 的卡還是畫，但變淡、寫「沒有要處理的」。整排都是 0 的時候，這一塊收成一行「今天沒有待辦」。載不到的卡寫「載不到」，不寫 0，0 跟載不到是兩回事。

**第三塊：你的 team。** 你在幾個 team 就幾段。每段三行：這個 team 開放中的申請表（N 份，連過去）、這個 team 的資源（N 條，連過去）、這個 team 的 Director 是誰。Co-President 看到的是六個 team 全部，一段一段排。這一塊回答你說的「每個人每個 team 有自己的地方」：不是幫每個 team 開一個資料夾，是首頁上每個 team 一段，點進去的清單預設篩成那個 team。

一般幹部（member）看到的首頁最短：身分一行、申請一卡（唯讀）、自己 team 一段。它仍然是一個 dashboard，只是短。

首頁最下面留一行小字：「對外七頁的文字在 HTML 檔裡，改法見 README」。這句 2026-10-15 定的，留著。

### 2-2. 導覽：兩個方案

兩個方案分組都不變，還是四組，`GROUPS` 那張表一字不改（`test/admin-hub.test.mjs` 守著四份一致）。差的是這四組怎麼擺。

**方案甲：一條導覽，兩層合一，位置釘死。**

頂欄底下一條橫的導覽：上排四組，下排當前那一組的分頁。它永遠在內容的最上面、位置固定、不隨分頁變。每一頁的標題與說明搬出卡片，成為「頁首」；卡片只裝清單或表單。

- 好處：改動最小。寬度不變、`index.html` 的結構幾乎不動，四個資料夾各改 `tabsHTML()` 的位置與樣式就有一半效果。
- 壞處：還是藥丸鈕，只是排整齊了。「我在哪」靠顏色深淺，手機上兩排藥丸會折成三四行。長清單的問題（33 格、25 人）它沒有解。而且它看起來還是「一個網頁」，不是你說的 dashboard。

**方案乙：側欄 Dashboard。**

頂欄底下分左右：左邊一條 220px 的側欄，右邊是內容。側欄從上到下：

```
後台
你：王平・Co-President・Sponsorship Team

首頁                      ← 今天要處理的事
申請
  申請表
對外
  資源
  團隊頁                 3   ← 待核可的數字，有才顯示
  校友頁
  信件文案
護照
  幹部護照
  實習護照
人與權限
  幹部名單
  邀請碼
  變動紀錄
```

- 你在哪一頁，側欄那一格亮，上面那一組的名字也亮。四組與十一個分頁一次看完，不用點進去才知道裡面有什麼。
- 進不去的組整組變淡、不可點，滑過去一句「只有 Co-President 進得去」。這跟現在的灰字一樣，**只是畫面，門還是在資料庫**。
- 側欄跟著捲動黏在左邊（sticky），所以 33 格捲到 7 月的時候，左邊還是看得到「我在幹部護照」。
- 內容區最寬 900px，整體 1180px。頁首固定長相：標題、一句說明、右邊最多一顆主要動作（例如「開一份新的申請表」「加一格」「發一組新的碼」）。頁首底下才是區塊。
- 長清單加「這一頁裡的段落」：幹部護照頁首底下一排 11 個月的小連結，點了跳到那個月；幹部名單照 team 分段。這是純 HTML 的錨點，不是什麼新機制。
- 手機（寬度 720px 以下）：側欄收成頂欄底下一顆「後台選單」按鈕，點開是同一份清單，從左邊滑出來。開合用 checkbox 加 label 純 CSS，跟 `shared/nav.js` 的手機選單同一招。內容區滿版。
- 好處：一眼看出「我在哪、還有哪些地方」，就是你要的 dashboard。長清單有得跳。以後加一個分頁就是側欄多一行。
- 壞處：四個 `index.html` 的外殼要重寫（不是改一改），`#bt-root` 從 940px 變成 1180px 要跟 `shared/nav.css` 對齊一次。側欄的 HTML 在四個資料夾各有一份（跟分組列同一條規矩），要多一條測試守四份一致。工時大概是甲的兩倍。

### 2-3. 建議：方案乙

你要的是 dashboard，甲做出來還是一個排整齊的網頁。乙的代價是這一次多一天，換來的是之後每一個新功能都有一個明確的位置：側欄加一行。而且側欄把「我在哪」這件事從三層藥丸變成一張地圖，Director 第一次登入三秒內就知道自己有幾個地方可以去。

### 2-4. 一致的版面語言：`admin/admin.css`

四個資料夾現在各自在 `index.html` 裡寫一份 270 行的 CSS，而且已經開始不一樣（資源頁的分頁列位置就是這樣跑掉的）。這次把它們收成一份 `admin/admin.css`，四個 `index.html` 都 `<link>` 它。

為什麼可以放在 `admin/` 底下、不違反「`shared/` 極小」：它只給後台四頁用，不是全站的樣式表，`shared/` 一個檔案都不加。`check.sh` 要求每一個有 `<style>` 的頁面都要有「點下去要有回饋」與 reduced-motion 那兩段，所以每個 `index.html` 保留一個很短的 `<style>`，只裝那兩段加 `#bt-root` 的寬度，其他全部在 `admin.css`。`admin.css` 只用 `shared/brand.css` 的 token，不寫死任何色碼與字體家族，`check.sh` 的色碼白名單照樣會掃到它。

下面是 `admin.css` 要定義的東西。**每一頁只能用這些，不准自己再發明一種按鈕。**

| 類別 | class | 長相與規則 |
|---|---|---|
| 版面 | `.shell` `.rail` `.main` | 頂欄底下左右兩欄。`.rail` 220px sticky；720px 以下 `.rail` 收起來 |
| 側欄 | `.rail-me` `.rail-group` `.rail-item` `.rail-item.on` `.rail-item.off` `.rail-count` | 組名用 Barlow Condensed 小字全大寫；分頁是內文字；`.on` 深藍底米白字；`.off` 淡 45% 不可點；`.rail-count` 右邊一顆小數字，0 不畫 |
| 頁首 | `.page-head` `.page-head h1` `.page-head .lede` `.page-head .actions` | h1 用 Barlow Condensed 34px；`.lede` 一句話 14px；`.actions` 靠右，最多一顆 `.btn` 加一顆 `.btn.ghost` |
| 段落錨點 | `.jump` | 頁首底下一排小連結，跳到頁內的 `.section`。超過 6 個才用 |
| 區塊 | `.section` `.section h2` `.section .hint` | 一個 h2（20px）一塊。每一頁最多五塊。區塊之間 28px，不用卡片框，用間距分 |
| 卡片 | `.card` | 只有首頁的待辦與需要「這是一個東西」的地方才用（預覽框、發碼表單）。清單不用卡片 |
| 清單 | `.list` `.list > li` `.row-main` `.row-meta` `.row-actions` | 一筆一列，上面一條細線分隔。`.row-main` 名字加徽章；`.row-meta` 一行 13px；`.row-actions` 靠右，最多三顆，第一顆 `.btn.sm.ghost`，其他 `.btn.quiet` |
| 表格 | `.table` | 只給幹部名單與城市：欄位固定、每列一行。720px 以下自動變成 `.list` 的長相 |
| 表單 | `.field` `.field label` `.field .help` `.grid-2` `.form-foot` | label 小字全大寫在上；`.help` 一句說明在輸入框下面（不是上面）；`.grid-2` 兩欄，560px 以下一欄；`.form-foot` 固定在表單底部，左邊「存起來」右邊「取消」，而且表單超過一屏時它黏在底部（sticky bottom）。這解決「改完主旨要捲到底才存得到」 |
| 按鈕 | `.btn` `.btn.ghost` `.btn.quiet` `.btn.sm` `.btn.danger` | 四種，不准再多。一列裡只有一顆 `.btn` 實心。`.danger` 給「刪掉」「停用」，框線橘、字深藍，不用紅色（Brand Book 沒有紅） |
| 徽章 | `.tag` `.tag.open` `.tag.draft` `.tag.closed` `.tag.done` `.tag.warn` | 裡面一定有字。五種底色對應開放／草稿／關閉／完成／注意，字一律深藍 |
| 訊息 | `.msg` `.msg.ok` `.msg.err` `.msg.info` | **三種分開**：`.ok` 蒂芬妮綠底「存好了」；`.err` 橘底、開頭固定「沒有存成：」加原因；`.info` 灰底，系統說明。位置固定在頁首底下，不在表單中間 |
| 提醒 | `.note` | 「核可前確認三件事」這類注意事項。淡沙色底、左邊一條深藍線、13.5px。一頁最多一個，而且收在區塊的 h2 底下，不是頁面最上面 |
| 空狀態 | `.empty` `.empty b` `.empty p` `.empty .btn` | 一句粗體講「這裡還沒有東西」，一句講「要怎麼開始」，一顆按鈕直接做。不置中、靠左，跟清單對齊 |
| 載入中 | `.skeleton` | 三條淡灰的長方形，不是一行「載入中…」。超過 300ms 才顯示，不然會閃 |
| 內嵌表單 | `.inline-form` | 取代 `prompt()`。按「開一份新的申請表」後，按鈕的位置展開一個小表單：名字、team、種類、「建立」「取消」 |
| 預覽框 | `.preview` | 護照預覽用。標題列、三顆文字鈕、底下 iframe。框高度固定 640px，裡面可以捲 |

字體：標題 `var(--display)`，內文 `var(--body)`。**後台不載 Noto Sans TC 與 Iansui**，跟現在一樣，理由在 `shared/brand.css` 檔頭（海外幹部的網路）。

顏色：七色 token，深淺調透明度。側欄底是 `--paper` 加一道極淡的 `--bt-sand`，內容區純 `--paper`。**不做深色側欄**，整站是亮的、暖的、紙的，深色側欄會變成另一個網站。

### 2-5. 每一頁改什麼

功能不加不減。這一張表是搬家清單。

| 頁 | 現在 | 改成 |
|---|---|---|
| `/admin/` 首頁 | 目錄卡加申請管理卡 | 2-1 的三塊。申請表清單搬到側欄「申請 > 申請表」 |
| 申請表清單 | 一張卡，表單一列 | 頁首「申請表」加右邊「開一份新的申請表」（展開內嵌表單，不再用 `prompt()`）。清單一列：名字、狀態徽章、team、收到 N 件其中 M 件沒處理。Co-President 看到的照 team 分段 |

**合併、改名、搬位置的三個決定**，理由寫在這裡：

- **「信件文案」留在「對外」，不搬去「申請」。** 它是申請流程的信，搬去申請很合理。但它只有 Co-President 改得動，而申請那一組是所有幹部進得去的；放在一組裡會變成「同一組裡有一個分頁你永遠進不去」。對外那一組本來就是 Co-President 為主。留著。
- **幹部護照與實習護照仍然是兩頁，不合併。** 它們的門不一樣（一個只有 Co-President，一個 Internship team 也進得去），格子的形狀也不一樣（綁月份對綁分類）。合成一頁會讓 Internship team 的幹部看到一整頁灰掉的幹部護照。側欄上它們是同一組底下的兩行，這樣的關係就夠了。
- **城市、變動紀錄各自獨立成一頁。** 兩個都是「偶爾才看一次、但看的時候要找得到」的東西。塞在長頁的最底下等於沒有。

### 2-6. 以後加功能怎麼加

這一段是寫給明年接手的幹部的，會原樣搬進 README。目標是沒寫過程式的人照著做得出來。

> **加一個新的後台分頁要做的事**
>
> 假設你要加「活動行事曆」到「對外」那一組。
>
> 1. **決定它屬於哪一組。** 四組是：申請（所有幹部）、對外（資源所有幹部，其他 Co-President）、護照（Internship team 與 Co-President）、人與權限（Co-President）。選了組就等於選了誰看得到，因為那一組的資料夾開頁第一句就在檢查。
> 2. **在側欄加一行。** 打開那一組的 `src/ui.js`，找到 `ITEMS` 那張表（跟 `GROUPS` 在一起），在對的組底下加一行：`{ group: "site", key: "calendar", label: "活動行事曆", who: "cadre" }`。**四個資料夾的 `ui.js` 各有一份 `ITEMS`，四份都要加同一行**，不然會變成「在 A 頁看得到，到 B 頁不見了」。跑 `node --test test/admin-hub.test.mjs` 會告訴你哪一份漏了。
> 3. **畫那一頁。** 在同一支 `ui.js` 加一個函式 `calendarHTML(rows, msg, busy)`，回傳一串 HTML。照這個骨架抄：
>    ```
>    pageHead("活動行事曆", "這一屆對外的活動，一列一場。", [{ act: "new-event", label: "加一場", primary: true }])
>    + msgHTML(msg)
>    + sectionHTML("接下來的活動", rows.length ? `<ul class="flist">${rows.map(row).join("")}</ul>` : emptyHTML("還沒有活動", "加第一場。"))
>    ```
>    `pageHead`、`msgHTML`、`sectionHTML`、`emptyHTML`、`skeletonHTML` 這五個小函式每一支 `ui.js` 都有，長相由 `admin/admin.css` 決定，你不用寫 CSS。
> 4. **接資料。** 在 `src/data.js` 加 `loadEvents()`。這一支檔案是這個資料夾裡**唯一**碰資料庫的，別的檔案不准 `from("...")`。
> 5. **接點擊。** 在 `src/main.js` 的 `onClick` 裡加 `if (act === "new-event") { ... }`。照旁邊已經有的抄。
> 6. **門在資料庫，不在畫面。** 如果這一頁會改東西，資料庫要有一支函式，第一句是 `is_president()` 或 `is_director_of()`。側欄把它灰掉只是提醒，不是安全機制。這一步要開遷移檔，先問 Co-President。
> 7. **跑三個檢查**：`node --test test/*.test.mjs`、`./check.sh`、`node scripts/check-mobile.mjs`。全綠才 commit。
> 8. **README 加一段**：這一頁做什麼、誰進得去、資料在哪張表。

這八步裡，1、2、3、8 不需要會寫程式（抄一行、改幾個字）；4、5 要看得懂旁邊的程式碼照抄；6 要找人。這跟現在的「開一個資料夾、放一個 HTML」同一個等級，沒有變難。

### 2-7. 視覺

對齊 `docs/2026-09-07-官網視覺方向.md`：

- **亮的、暖的、紙的。** 底 `--paper`，右上角一道 `--bt-sand` 暖光跟護照、時間看板同一條。側欄不做深色。
- **深藍是字與結構，橘是「在動的東西」。** 待辦卡上的數字用深藍 Barlow Condensed 44px，按鈕 hover 變橘，批次列滑上來的時候是橘底。
- **靠左、不對稱。** 頁首靠左、空狀態靠左、數字靠左。整個後台沒有一個置中的東西。
- **不做它那一節「明確要避開的套路」裡的任何一條**：沒有 eyebrow 小標疊在標題上（現在的 label 小字全大寫只在表單欄位用，那是功能不是裝飾）、沒有中點串 meta（現在到處都是「・」，改成空格加淡字）、沒有一樣圓角一樣陰影的卡片海（清單不用卡片）、按鈕後面沒有箭頭。
- **動的東西只有三個**：側欄當前那一格的底色、批次列從底部滑上來、訊息出現。全部 150ms，`prefers-reduced-motion` 一律關。
- 「真的好看」的判準我拿來自己對照的三個：第一眼看到的是數字不是按鈕；任何一頁截圖出來沒有兩種以上的框；手機上一屏內看得到第一個可以做的事。

## 3. Loop 自檢

### 第一輪：一位第一次登入的 Director，三秒內知不知道該點哪裡

把自己當成 Marketing team 的 Director，第一次打開 `/admin/`。

抓到四件，都修了：

1. 第一版的首頁第一塊只寫「你是 Director」，沒寫 team。Director 的權限是「職位加 team」兩個一起算的，少一個他就不知道為什麼看不到 Curriculum 的申請。**修法**：那一行固定「名字、職位、team」三個都寫。
2. 第一版待辦卡的「還沒處理的申請」按下去到 `/admin/` 申請表清單，他還要再找哪一份有待審。**修法**：按下去直接到第一份有待審的表單的審核分頁。只有一份就不用選。
3. 側欄上「人與權限」整組灰掉，但第一版沒寫為什麼。他會以為壞了。**修法**：灰掉的組滑過去一句「只有 Co-President 進得去」，手機上（沒有滑過去）那一行直接寫在組名底下。
4. 「你的 team」那一塊第一版只有 Co-President 看得到六個 team。Director 只看自己的，但一個人可以在好幾個 team（2026-09-10 起），第一版只畫第一個。**修法**：有幾個畫幾段。

三秒測試：打開，看到自己的名字與職位，底下第一張卡「還沒處理的申請 5 件」加一顆「去審」。過。

### 第二輪：一位沒寫過程式的下一屆幹部，照 2-6 做不做得出來

把自己當成 2027-08 接手的人，手上只有 README 與這份文件。

抓到三件，都修了：

1. 第一版 2-6 說「在 `ITEMS` 加一行」，但沒說 `ITEMS` 長什麼樣、在檔案的哪裡。**修法**：寫明「跟 `GROUPS` 在一起」，而且那一行的格式直接貼出來。
2. 第一版第 3 步叫他「照 2-4 的 class 寫 HTML」。他不會寫 HTML。**修法**：每一支 `ui.js` 提供 `pageHead`、`msgHTML`、`section`、`listHTML`、`emptyHTML` 五個小函式，他只要拼，不用寫 class。這五個函式四個資料夾各一份，`test/admin-hub.test.mjs` 加一條守四份一字不差。
3. 第一版沒講「哪幾步不用會寫程式」，他看到八步會整個放棄。**修法**：最後加一段分級。

另外確認：`admin/admin.css` 一份、四個 `index.html` 都連它，所以他加新頁完全不用碰 CSS。這比現在（四份 270 行 CSS 各自抄）好接手。
