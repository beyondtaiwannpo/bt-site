# 會議紀錄與排會（2026-10-24 設計）

Paul 清單的第 1、2 項，合在一起設計，因為都踩在每週時間看板上：
1. **會議紀錄**：紀錄今天在 Google Drive 的文件裡。後台要一個「會議」區：日期時間、標題、出席的人（從名單勾）、Drive 文件的連結、一行議程；列過去的與之後的；分 team 或整個 BT。**不嵌文件內容**，只放連結（跟 `/resources/` 同一條規矩：檔案留在 Drive）。
2. **從內部工具排會，放上 Google 日曆，用 Beyond Taiwan 的信箱寄邀請**：在 `/availability/`（每週時間看板）挑一格 → 勾出席的人 → 建一筆會議（第 1 項那一筆）→ Google 日曆上有這場 → 從 BT 的信箱寄邀請信。

這份先盤點、再設計、停下來等 Paul 批，**還沒寫程式**。

## 設計

### 第 1 項：會議紀錄

一張表 `meetings`：

| 欄 | 是什麼 |
|---|---|
| `id` uuid | |
| `scope` | `board`（整個 BT）或一個 team 名 |
| `title` text | 標題 |
| `starts_at`、`ends_at` timestamptz | 時間（存 UTC，每個人照自己的時區看） |
| `agenda` text | 一行議程（可以空） |
| `doc_url` text | Drive 文件的連結（只收 `https://docs.google.com/` 或 `https://drive.google.com/`，可以空，開會後再補） |
| `created_by`、`created_at`、`updated_at` | |

`meeting_attendees`（會議 × 幹部）：`meeting_id`、`user_id`、`status`（`invited`／`accepted`／`declined`，第 2 項會用）、`invited_at`。

RLS：幹部讀全部（會議紀錄本來就是內部公開的，連結點進去 Drive 自己守權限）；寫走函式：`save_meeting()`（建與改：senior、或 scope 是 team 時那個 team 的資源工作區「管」的人，也就是 Director）、`delete_meeting()`（同一批人）。出席的人自己可以改自己那一筆的 `status`。

後台：側欄「申請」那一組底下多一行「會議」（每一位幹部）。一頁兩段：**之後的**（照時間近到遠）、**過去的**（照時間新到舊，預設最近 90 天，「更早的」展開）。每一列：日期時間（照看的人的時區，旁邊印台北時間）、標題、整個 BT 或哪個 team、出席幾人、「紀錄」連結（有 `doc_url` 才有）。能建會議的人有「記一場會議」（手動補一場已經開過的，或還沒排的）：時間、標題、範圍、出席的人（多選那一塊）、議程、Drive 連結。總覽多一張卡「這一週的會議：N」。

### 第 2 項：從看板排會

在 `/availability/` 看板上，點一格現在會跳出 peek（各地時間、加到我的 Google 日曆）。senior 與 Director 多一顆「**排一場會**」：
1. 帶著那一格的時間（預設一小時，跟現在一樣；可以改長度）。
2. 勾出席的人：多選那一塊，預設勾「這一格有空的人」（看板本來就知道誰有空），可以加減；範圍（整個 BT 或哪個 team）從勾的人推，也可以手選。
3. 標題（預設「BT 會議」，Paul 2026-09-02 定的）、一行議程、Drive 連結（可以先空）。
4. 按「排會並寄邀請」→ `schedule_meeting()`：寫 `meetings` 與 `meeting_attendees`、排一封 `meeting_invite` 給每一位出席的人、直接寄（跟需求單一樣）。

**Google 日曆那一側，老實講**：GitHub Pages 沒有伺服器，瀏覽器不能拿 BT 帳號的憑證去寫日曆。兩條路：

| | (b) 不用 API：信裡附 `.ics`、加一顆「加到 Google 日曆」連結 | (a) Supabase Edge Function 拿 BT 帳號的 refresh token 寫 Calendar API |
|---|---|---|
| 要什麼 | 什麼都不用。`.ics` 是函式裡拼的純文字，Resend 本來就能帶附件；連結是現有的 `googleCalUrl()` | Paul 做一次 OAuth 同意（BT 的 Google 帳號）、refresh token 放 Vault、一支 Edge Function、`send_pending_mail` 之外多一條呼叫 |
| 誰加到日曆 | **出席的人自己**按一下（信裡那顆或附件）。BT 帳號的日曆不會自動多這一場 | 建在 **BT 帳號的日曆**上，出席的人是 Google 邀請的 guest，Google 自己寄 Google 那封、自己處理接受拒絕 |
| 帳號換掉（之後搬到網域帳號） | 寄件位址在 Resend 設定一個地方換 | 重做一次 OAuth，token 換掉，一個地方 |
| 壞掉的樣子 | 沒有會壞的東西 | token 過期（Google 對「測試中」的 OAuth app 七天就收回）、API 配額、Edge Function 冷啟動 |
| 交接 | 看得懂信就看得懂 | 多一個只有做過 OAuth 的人懂的東西（北極星扣分） |

**建議 (b) 做第一版，(a) 留著當升級路**：第一版要的是「大家都收到、按一下就在自己日曆裡」，(b) 做得到；「BT 帳號的日曆上也有」是 (a) 才有的，等 BT 搬到網域帳號（那時 OAuth app 可以設成內部，token 不會七天收回）再做比較划算。設計上把「放上日曆」做成一個可以換的步驟：`schedule_meeting()` 只負責寫表與排信；信裡那顆「加到 Google 日曆」與 `.ics` 是第一版；之後 (a) 是在同一個地方多叫一支函式。

**提醒信**：開會前 24 小時一封 `meeting_reminder`，排進 outbox 再寄。要有人在那個時間點叫 `send_pending_mail`：
- **pg_cron**：這個 repo 的遷移檔沒有用過；Supabase 的 pg_cron 擴充所有方案都有（含免費），但要 Paul 在 Dashboard → Database → Extensions 打開一次，我在這裡確認不了他的專案有沒有開。開了就一條：每 15 分鐘跑 `queue_meeting_reminders()`（把 24 小時內要開、還沒提醒過的會排信）加 `send_pending_mail(20)`。
- 沒開 pg_cron 的退路：提醒信排進 outbox，**下一個進後台的人**開總覽那一刻送出（總覽本來就有「還沒寄出去的信」那張卡；可以改成自動送）。24 小時前的提醒變成「24 小時內有人開過後台就寄」，30 個人的組織通常成立，但不保證。

**誰能排會**：senior 排任何會；Director 排自己 team 的（scope 是他是資源工作區「管」的那個 team）；Associate 不能排，但可以「記一場會議」補紀錄嗎？建議不行，統一同一群人，少一條規則。

**出席的人能不能從信裡拒絕**：建議可以，但簡單做：信裡兩顆「會到」「不能到」連結，連到 `/availability/?meeting=<id>&rsvp=accepted|declined`，登入後那一頁叫 `rsvp_meeting()` 改自己那一筆。不做不用登入的一次性連結（那是又一套 token）。排會的人在會議那一頁看到誰會到。

## 不做

- 不嵌 Drive 文件內容、不同步文件、不做站內編輯器。
- 不做議程的多行結構、不做待辦追蹤、不做投票。
- 不幫人改他的「有空」格子；看板只是挑時段的參考。
- 不寄 Google 那套邀請（第一版沒有 Calendar API）。
- 不在 `shared/` 加檔案；多選那一塊已經在四份 admin `ui.js` 裡，看板要用會再抄一份到 `availability/src/`（資料夾之間不 import，是這個 repo 的規矩）並加逐字比對的測試。

## 安全與 GOALS 這一輪

- `/availability/` 本來就要登入且只有幹部（`role = cadre`），排會的門在資料庫（`schedule_meeting()` 第一句檢查 senior 或那個 team 的「管」）。
- 出席者的 email 由函式從 `auth.users` 拿，前端送不進任何 email。
- 信裡不放任何人的 email 或名單以外的個資；RSVP 連結要登入才生效。
- `doc_url` 只收 Google Docs／Drive 的 `https://`。
- 寄件帳號換掉：Resend 的寄件位址一個地方；之後 (a) 的 token 在 Vault 一個地方。
- GOALS「不做站內通知中心」：狀態變了就寄信，這裡照做；「資料與動畫分離」不相干；`shared/` 不動。
