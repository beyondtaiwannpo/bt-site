## 第一階段：不用碰資料庫（五分鐘）

### 0. 把網站跑起來

打開終端機，貼這兩行：

```
cd ~/Code/bt-site
python3 -m http.server 8000
```

看到 `Serving HTTP on :: port 8000` 就成功了。**這個視窗要一直開著**，
關掉網站就停了。測完按 `Ctrl + C` 停掉。

然後瀏覽器打開 <http://localhost:8000/>。

> ⚠ **不要用瀏覽器直接開 `index.html`。** `file://` 底下 JavaScript 模組會被
> 瀏覽器擋掉，畫面是空白的，而那個錯誤看起來就像「網站壞了」。

## 第二階段：資料庫（做完就可以上線）

Supabase 後台：<https://supabase.com/dashboard> →
專案 `norjaglyaotzewxavmhv`。

### 4.5 先在自己電腦上跑一次（選做，但很快）

```
./scripts/db/smoke.sh
```

需要本機有 Postgres。它會開一個用完就刪的暫時資料庫，把六支跑一遍加走一次流程。
**看到「全部通過」再去動 Supabase**，這樣真的出錯的時候你就知道
問題出在 Supabase 那邊，不是 SQL 本身。

### 5. 依序跑七支遷移檔

> ⚠ **用 `pbcopy` 複製，不要用滑鼠選。**
> 2026-09-08 第一次跑就是貼到一半被截斷，錯誤訊息是
> `unterminated quoted string`，看起來像 SQL 有錯，其實是內容不完整。
> 在終端機打這一行，整個檔案就進剪貼簿了，然後到 SQL Editor 直接貼：
>
> ```
> pbcopy < ~/Code/bt-site/supabase/migrations/2026-09-08-students.sql
> ```
>
> 六支就換六次檔名。**貼完先看一眼最後一行是不是 `-- ` 開頭的說明文字**，
> 是的話代表整份都進去了。

左邊選 **SQL Editor** → **New query**，
把檔案整份貼進去、按 **Run**。**一次一支，照這個順序**：

1. `supabase/migrations/2026-09-08-students.sql`
2. `supabase/migrations/2026-09-09-applications.sql`
3. `supabase/migrations/2026-09-10-decisions-and-mail.sql`
4. `supabase/migrations/2026-09-11-resources.sql`
5. `supabase/migrations/2026-09-12-event-ops.sql`
6. `supabase/migrations/2026-09-13-public-team.sql`
7. `supabase/migrations/2026-09-14-anon-execute.sql`

- [ ] 七支都跑完，而且每一支都是 **Success**

順序不能換，後面幾支要用前面建的東西。
每一支都包在一個 transaction 裡，**中途任何一句失敗就整份回滾**，
不會留下做到一半的狀態。看到紅字就整段複製給我。

### 6. 指定第一位 president（只有這一次要手動）

沒有這一步的話，後台沒有任何人開得了表單，而畫面上不會說原因。

在 SQL Editor 跑（把信箱換成你自己的）：

```sql
update public.profiles set board_role = 'president'
 where id = (select id from auth.users where email = '換成你的信箱');
```

Alysia 那一份再跑一次（換成她的信箱）。

- [ ] 確認一下，這一句應該回**剛好兩列**：

```sql
select name_zh, team, board_role from public.profiles where board_role <> 'member';
```

### 7. 讓信寄得出去

**兩件事，缺一個信就會安靜地寄不出去**（後台看得到「還有 N 封沒寄出去」）。

1. **開 pg_net**：Database → Extensions → 搜尋 `pg_net` → 打開
2. **放兩個 secret**：Project Settings → Vault → New secret
   - `RESEND_API_KEY`：Resend 後台的 API key（`re_` 開頭）
   - `BT_MAIL_FROM`：例如 `Beyond Taiwan <noreply@beyondtaiwannpo.com>`

> ⚠ 金鑰不要貼進這個 repo 的任何檔案，它是公開的。

- [ ] 跑一次 `select public.send_pending_mail(1);`，
      回 `(0,0)` 是正常的（現在還沒有信要寄）。
      如果回 `mail_not_configured`，代表上面兩件事有一件沒做完。
